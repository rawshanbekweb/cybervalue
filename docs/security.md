# Security decisions

No public mutation, public upload or self-registration endpoint is exposed. `/admin` is a private, single-account area for the site owner; there is no signup form, and the account is provisioned only by the operator-run `npm run admin:create-user` script. `User.passwordHash` uses `node:crypto` scrypt (`N=16384, r=8, p=1`, random 16-byte salt, timing-safe comparison), never a third-party hashing dependency. A wrong email and a wrong password return the same generic message, and a nonexistent email is verified against a dummy hash so both cases take about the same time, avoiding an account-enumeration timing signal. Login attempts and admin writes are separately rate-limited through the same process-wide limiter used by downloads (`src/lib/rate-limit.ts`).

Sessions are database-backed (`Session` model): a random 32-byte token lives only in an `httpOnly`, `sameSite=lax` cookie scoped to `/admin` (`secure` in production), while the database stores just its SHA-256 hash and an expiry (12 hours, no silent refresh). Logging out deletes the row, so revocation is immediate — unlike a stateless/JWT session. Every admin page and every mutation independently calls the same session check (`requireAdmin`/`getSession` in `src/lib/auth.ts`); a page-level redirect does not by itself protect the underlying Server Action, per [Next.js's own guidance](https://nextjs.org/docs/app/guides/data-security#authentication-and-authorization).

Content, account and file deletion mutations use Server Actions with Next.js Origin checks. The raw binary `POST /admin/uploads` route independently requires a same-origin request and an authenticated session before reading the body. `/admin/**` is dynamic and disallowed in `robots.txt`; private file responses use no-store/noindex. Content writes invalidate affected public routes and the sitemap.

Uploads are bounded to 4 MiB while reading the stream, independently of Content-Length. Allowed extensions are fixed; PDF/ZIP signatures and UTF-8 text are checked. Raster images are decoded with a pixel limit and re-encoded to WebP, stripping metadata. SVG, executable extensions, animated and malformed images are rejected. Names are generated randomly; original names are display metadata. StoredFile bytes live in PostgreSQL, with a 250 MiB quota. Quota checks, deletion and content references use a transaction advisory lock to prevent concurrent removal of referenced files. These checks do not constitute malware scanning.

The public download route checks publication before serving either stored or legacy disk files. Uploaded images are exposed only if referenced by published content and bypass Next.js image optimization caching so an archived image becomes unavailable immediately at the application. Existing public/images assets remain public. Admin creation rejects duplicate slugs, edits bind to an existing ID and slug, and status/delete operations are collection-scoped. Mutations and uploads are rate-limited. Account password changes require the current password and revoke all sessions; the owner can also revoke other sessions without signing out the current one. Password hashes are excluded from content author selections.

Public queries enforce `PUBLISHED`, a non-null publication date no later than now, and authorization for labs. Slug validation and collection matching apply to detail and OG routes. Relationships and sitemap use the same public predicate. Downloads query publication directly and never serve draft files from the public directory.

Markdown is parsed without raw HTML/MDX, passed through rehype-sanitize, and encoded by React. The default Markdown URL transformer rejects dangerous schemes. Inline images are ignored; approved local images use next/image. Dynamic JSON-LD escapes `<`. Import URLs accept HTTPS only, with no embedded credentials. Query lengths, pagination, taxonomy and enum values are bounded. Prisma query builders parameterize database values.

CSP restricts resources to self, disallows frames/objects, and restricts forms/base URI. Inline scripts/styles remain allowed because statically generated Next.js pages embed bootstrap data. This is a deliberate limitation: CSP is not a complete inline-XSS defense. A nonce policy requires dynamic rendering, or a verified hash/SRI deployment pipeline. Development additionally permits eval and websocket connections. HSTS is set for production; HTTPS must be configured at the host.

Downloads have a global per-process budget of 30 per minute. It does not trust `X-Forwarded-For`, which clients can spoof unless a proxy sanitizes it. The Map is bounded and expires entries. For a public multi-instance deployment, enforce per-client rate limits at the trusted edge/WAF, and cap request sizes there. The Node limiter is not a distributed abuse-prevention system. Archive filtering is bounded but should also be protected by host-level request limits at scale.

Download filenames are allowlisted and contained in a fixed private directory; symbolic links are rejected, size is capped, and responses force attachment with nosniff/no-store/noindex. Only the trusted operator can write resource files. Downloads are intentionally buffered under a 20 MiB limit. Files are not automatically scanned; operator review is required before publishing.

ISR can still retain previously public content briefly while a stale page is served and regenerated in the background, and other deployment instances or a CDN in front of the app won't see the admin's `revalidatePath` call. Do not store secrets in any published record. For urgent unpublishing across a multi-instance deployment, also purge CDN/ISR caches or redeploy.

Never print environment secrets. Error UI hides stack traces; download errors return generic messages. Use least-privilege database credentials and TLS in production. Keep dependencies and lockfile maintained. Store backups and test restoration independently of the site deployment.
